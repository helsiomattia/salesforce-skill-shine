# Tarefa: Corrigir problemas de qualidade do projeto salesforce-skill-shine

Você vai trabalhar no projeto **salesforce-skill-shine** (SPA React 18 + TypeScript + Vite, React Router v6, Tailwind, i18next pt/en/es). Aplique as correções abaixo na ordem de prioridade indicada.

## Regras gerais (não violar)

- NÃO invente backend, autenticação, banco de dados ou APIs. O projeto é 100% client-side.
- NÃO remova dados de domínio (`src/data/competencies/*`, `src/data/guideData.ts`) sem validar todas as rotas e componentes que os consomem.
- PRESERVE i18n em pt/en/es: todo texto novo visível ao usuário vai para `src/locales/{pt,en,es}/common.json`, com as três línguas sincronizadas.
- NÃO persista dados pessoais além do comportamento atual.
- Ao terminar CADA bloco, valide com `npm run build` e `npm test`. No bloco de lint, valide também com `npm run lint`.
- Se mexer em rotas publicadas, revise `public/sitemap.xml`, `public/404.html`, `index.html` e `vite.config.ts`.
- Faça commits separados por bloco, com mensagens claras.

## PRIORIDADE 1 — Estabilização

### 1.1 Corrigir o lint até `npm run lint` passar sem erros
- `@typescript-eslint/no-explicit-any` em: `src/components/ResultsPanel.tsx`, `src/components/layout/Sidebar.tsx`, `src/components/layout/TopNav.tsx`, `src/pages/GuidePage.tsx`, `src/pages/GuideDetailPage.tsx`. Substitua cada `any` por tipos reais (crie/importe os tipos necessários; o `getNavItems` do `TopNav` deve ter tipo de retorno explícito).
- `@typescript-eslint/no-empty-object-type` em `src/components/ui/command.tsx` e `src/components/ui/textarea.tsx`. Troque interface vazia por `type X = React.ComponentProps<...>`.
- `@typescript-eslint/no-require-imports` em `tailwind.config.ts`. Migre `require()` para `import`.
- Resolva os warnings `react-refresh/only-export-components` onde for viável sem quebrar os wrappers de UI.
- Critério de aceite: `npm run lint` retorna 0 erros.

### 1.2 Resolver o CI/deploy fantasma
- O `README.md` afirma deploy automático via GitHub Actions, mas não existe `.github/workflows`.
- Ação preferida: criar `.github/workflows/deploy.yml` que rode em push na branch `main`, execute `npm ci`, `npm run lint`, `npm test`, `npm run build` e publique `dist/` no GitHub Pages (respeitando o base path `/salesforce-skill-shine/`).
- Se não for criar o workflow, corrija o `README.md` para refletir a realidade.

### 1.3 Testes de smoke mínimos
- Substitua o teste trivial `src/test/example.test.ts`.
- Crie testes de smoke que montem cada rota principal sem erro: `/`, `/assessment`, `/assessment/admin`, `/guide`, `/guide/:id`, `/contact`, `/privacy`, e o wildcard `*` (NotFound).
- Adicione um teste unitário para a lógica de cálculo do `ResultsPanel` (média, forças, gaps) — é lógica pura, priorize.
