Analise tecnicamente este projeto inteiro e produza uma documentação completa da implementação atual.

Não altere nenhum arquivo do projeto nesta etapa.

Sua tarefa é inspecionar o repositório e documentar somente o que puder ser comprovado pelo código e pelos arquivos de configuração. Não presuma tecnologias, padrões ou funcionalidades.

## 1. Escopo da análise

Leia, quando existirem:

- package.json
- package-lock.json, yarn.lock, pnpm-lock.yaml ou bun.lock
- tsconfig.json e arquivos relacionados
- vite.config.*
- next.config.*
- tailwind.config.*
- postcss.config.*
- eslint.config.* ou .eslintrc*
- prettier.config.* ou .prettierrc*
- arquivos de ambiente de exemplo
- README
- estrutura completa de src/
- componentes
- páginas
- layouts
- rotas
- hooks
- contexts
- stores
- services
- APIs
- tipos e interfaces
- utilitários
- testes
- workflows do GitHub Actions
- configurações de deploy
- arquivos públicos e assets

Ignore:

- node_modules
- dist
- build
- coverage
- arquivos gerados
- caches
- binários
- dependências vendorizadas

## 2. Regra de evidência

Toda conclusão técnica deve citar os arquivos que comprovam a informação.

Exemplo:

- React 18 — evidência: `package.json`
- TypeScript com modo strict — evidência: `tsconfig.json`
- Roteamento com React Router — evidência: `src/App.tsx` e `src/routes/...`
- Deploy no GitHub Pages — evidência: `.github/workflows/deploy.yml`

Quando não for possível confirmar algo, escreva:

> Não foi possível confirmar com os arquivos analisados.

Não invente:

- arquitetura;
- banco de dados;
- backend;
- autenticação;
- testes;
- CI/CD;
- integrações;
- padrões de projeto;
- bibliotecas não encontradas no repositório.
